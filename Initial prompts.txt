Now the wrapper. The key fact first: whichever you pick, the app itself is the same React + TypeScript code, and it runs in a normal browser during development. The wrapper is just the shell it ships in, added at the final phase. So this ruling can wait until you've been using the app for weeks.

**Option 1: no wrapper (browser only).** You start it with one command and it opens in a browser tab. Edge can also "install" it as an app, which gives it its own window and Start menu icon, still with nothing extra on your machine. Zero packaging work, ever. Two real drawbacks. There is no true .exe, so something has to serve the app. And your training progress lives in browser storage, which is wiped if you ever clear site data. The export button in the brief exists for exactly that risk, but real files are safer.

**Option 2: Electron.** Bundles a full copy of the Chrome engine and Node inside your app. You get a proper installer and .exe, and the whole toolchain stays JavaScript, so nothing new to install. The cost is bulk: roughly 200-300 MB on disk and a couple of hundred MB of memory for what is a small training tool. It is the most battle-tested option (VS Code and Slack are Electron apps).

**Option 3: Tauri.** Also wraps the web app, but instead of shipping a browser it uses WebView2, the Edge-based page renderer already built into Windows 11. The result is an .exe of a few MB, a much lighter memory footprint, and real file access, so progress is stored as files in AppData rather than browser storage. It could also run the full native Stockfish as a helper process later, though the in-browser engine is already far stronger than any training opponent needs. The cost: Tauri's shell layer is Rust, so a one-time toolchain install (rustup, plus the MSVC C++ build tools). If your Visual Studio setup already includes the C++ workload, the only new piece is rustup. The first build compiles for a few minutes, then it caches.

**What about WPF/.NET, given you know it?** Ruled out in the brief. Every ready-made piece this app needs (board widget, rules library, in-browser engine, repetition scheduler) is JavaScript. WPF would mean hand-building a board control and engine plumbing, which is weeks of work that teaches you no chess.

**My recommendation stays Tauri**: a real, small Windows app with durable file-based progress, at the cost of one toolchain install that Claude Code can script. Pick Electron if "no new toolchain, maximum boring reliability" appeals more than size. Pick browser-only if, honestly, an icon and an .exe don't matter to you.
